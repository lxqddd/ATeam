# ADR 0001：会话分享 / 同步的存储与隐私方案

- 状态：Accepted
- 日期：2026-11-27
- 关联：issue #7（依赖 #4 脱敏导出、#5 导入与 id 重映射）
- 决策范围：会话“分享”（单向发布）与“同步”（多设备往返）的存储后端、数据范围、链接与撤销语义、威胁模型；不包含生产实现

## 1. 背景

ATeam 目前是本地优先的桌面应用：会话保存在本机（JSON / SQLite），没有任何账号体系；导出（§1.7）与导入（§1.8）已经具备完整链路：

- 导出文档自带 `kind: "ateam-session-export"` 与整数 `schemaVersion`（当前为 1），支持 JSON / JSONL / Markdown 三种格式，三种格式都能重新导入；导入端拒绝更新的 `schemaVersion`（`EXPORT_NEWER_SCHEMA_VERSION`）。
- 凭据始终脱敏：敏感键（`apiKey`、`secret`、`password`、`authorization`、各类 token 等）与自由文本中的常见凭据形态（`sk-`、`ghp_` / `github_pat_`、`xox*`、`AKIA`、`AIza`、JWT、`Bearer`）替换为 `[REDACTED]`。
- 绝对路径默认替换为 `~` / `<PATH>`；附件只保留元数据（路径替换为 `<ATTACHMENT>`）；工具图片只保留数量；文件快照不写入导出。
- 导入总是创建新会话并重映射全部 id，丢弃运行簿记 parts，占位符不会被当作本地路径使用。

需要决定的是：用户想把一段会话分享给他人（发文件、发链接、发到社区），或想在多台设备间同步时，数据放在哪里、以什么格式和链接暴露、如何撤销、攻击面是什么。这些决定会约束后续所有分享 / 同步功能的实现方式，因此先以 ADR 固定方向。

### 约束

1. **本地优先**：应用当前无账号、无服务端；引入任何托管后端都会同时引入账户、配额、滥用处置与合规成本。
2. **密钥边界**：供应商 API Key 与 OAuth token 只存在于本机 `auth.json`（0600），渲染层不可见；分享链路不得扩大凭据暴露面。
3. **已有格式可复用**：导出 / 导入协议已经过脱敏与结构校验，分享应尽量复用而不是另造格式。
4. **不可撤回性**：任何离开本机的数据都可能被复制、转发、索引，撤销只能是“尽力而为”。
5. **分享 ≠ 同步**：分享是一次性快照；同步需要身份、写入冲突与删除墓碑语义，复杂度高一个量级。

## 2. 决策

**采用“本地文件优先、BYOS（bring your own storage）其次、托管服务最后”的分阶段方案：**

1. **Phase 1（本期方向，无需新基础设施）：分享 = 强制脱敏的导出文件。**
   - 复用 `ateam-session-export` 文档（`schemaVersion` 1），不引入新的分享格式；分享是导出的一种预设：路径脱敏强制开启、附件仅元数据、快照与工具图片不打包、凭据始终脱敏。
   - 不引入账号、不上传、不生成链接；文件通过用户自己的渠道（邮件、IM、云盘）传递，接收方用现有导入流程打开。
   - 界面必须明确提示：文件一旦发出无法撤回；分享前展示脱敏摘要供用户确认。
2. **Phase 2（可选便利后端，按需实现）：用户自带凭据的发布通道。**
   - 首选 **用户自有 Git 仓库**（用于同步方向）与 **GitHub Gist**（用于一次性公开分享）。两者都使用用户自己的账号与凭据，ATeam 不运营任何存储。
   - Gist 的 “secret” 只是“未列出”，拿到 URL 即可读取，界面必须如实说明，不得表述为“私有”。
3. **Phase 3（仅在需求被验证后）：端到端加密的托管分享服务。**
   - 服务端只存密文；密钥放在链接 fragment（`#` 之后），不会随 HTTP 请求发送给服务器。
   - 匿名分享 + 删除令牌即可满足需求，不默认建设账号体系。
4. **同步方向：只定方向，不在本 ADR 内解决。** 同步走 BYOS（用户自选目录或自有 Git 仓库）的本地优先模型；完整的同步协议（冲突、墓碑、压缩）需要独立 ADR 与实现 issue。
5. **分享是快照而非订阅**：已分享的内容不会随会话更新而更新；更新需要重新生成分享。

## 3. 后端比较

| 方案                                      | 成本                                         | 隐私                                                                              | 运维                                                   | 撤销                                            | 适用场景                                                      |
| ----------------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------- | ------------------------------------------------------------- |
| **本地文件 / 用户自有云盘（BYOS）**       | 边际成本约 0；存储由用户已付费的云盘承担     | 最高：数据只经过用户选择的存储；ATeam 不接触                                      | 无 ATeam 侧运维                                        | 不可撤销；文件复制后不可控                      | 个人间分享、跨设备中转；**Phase 1 默认**                      |
| **GitHub Gist（用户账号）**               | 免费；受 GitHub 配额与限流约束               | 中：由 GitHub 托管；secret gist 仅“未列出”，有 URL 即可读；内容可能被搜索引擎收录 | 低：复用 GitHub 认证与可用性，但需在应用内安全保存 PAT | 删除 gist 即从 GitHub 移除，但缓存 / 镜像不可控 | 面向社区的公开分享；**Phase 2 可选**                          |
| **自建 / 托管分享服务（ATEAM 或第三方）** | 高：服务器、带宽、存储、备份、滥用处置、合规 | 取决于设计：明文托管时服务端可见全部内容；E2E 时服务端只见密文与体积元数据        | 高：账户、配额、TTL、监控、值班、取证流程              | 删除接口即时生效（配合 TTL）；已转发副本不可控  | 需要短链、预览、受控撤销的产品化分享；**Phase 3，且必须 E2E** |
| **用户自有 Git 仓库（同步）**             | 免费或用户已有仓库                           | 中高：数据在用户仓库；公开仓库等于公开分享                                        | 无 ATeam 侧运维                                        | 删除需改写历史（困难）；依赖用户的仓库卫生      | 多设备同步、可审计的版本历史；**同步方向候选**                |

选择理由：

- Phase 1 直接复用已经过安全评审的导出 / 导入链路，零新增攻击面、零运维，符合本地优先定位。
- Gist 的“未列出 ≠ 私有”与 PAT 管理成本，使其不适合作为默认路径，但作为显式选择的公开分享足够轻量。
- 托管服务只有在“短链 + 撤销 + 低摩擦”成为刚需时才值得建设；一旦建设必须 E2E，否则服务端成为最大隐私风险点。
- 用用户自己的 Git 仓库做同步，避免账户体系，同时天然获得版本历史；代价是冲突处理与撤销困难，需独立设计。

## 4. 数据范围与脱敏规则

### 4.1 可分享的数据

分享文档与现有导出结构一致，包含：

- 会话元数据：标题、时间戳、模型引用（`providerId` / `modelId`）、推理强度、权限模式、todo、usage 与成本估算。
- 消息：用户与助手的文本、推理文本、工具调用（名称、输入、状态、输出截断后的内容）。
- 文件变更元数据：改动文件列表与增删行数等（随消息 part 一起导出）。

### 4.2 永不分享的数据

- 任何凭据：供应商 API Key、OAuth 客户端密钥、access / refresh token、`auth.json` 内容；分享链路只接收会话记录，不接触凭据存储。
- 附件二进制、工具产生的图片：只保留名称、类型、大小等元数据。
- 文件快照内容：快照是内容寻址 blob，不写入分享文档。
- 运行簿记：`snapshot` / `step-start` / `step-finish` / `patch` 等 parts 不参与分享（导入端同样会丢弃）。

### 4.3 脱敏规则（分享预设比私有导出更严格）

| 类别                                                                                       | 私有导出默认      | 分享（Phase 1 起）     |
| ------------------------------------------------------------------------------------------ | ----------------- | ---------------------- |
| 敏感键名（`apiKey`、`secret`、`password`、`authorization`、各类 token、`cookie` 等）       | 始终 `[REDACTED]` | 同上，不可关闭         |
| 自由文本中的凭据形态（`sk-`、`ghp_` / `github_pat_`、`xox*`、`AKIA`、`AIza`、JWT、Bearer） | 始终 `[REDACTED]` | 同上，不可关闭         |
| 绝对路径 / 家目录                                                                          | 默认脱敏，可关闭  | **强制脱敏**，不可关闭 |
| 附件内容                                                                                   | 不打包            | 不打包                 |
| 快照 / 工具图片                                                                            | 不导出            | 不导出                 |

补充要求：

- 分享前展示脱敏摘要（凭据数、路径数、被排除的附件数），用户确认后才生成文件。
- 单次分享文档大小设上限（建议 10 MB）；超出时提示用户先拆分会话，而不是静默截断。
- 脱敏是模式匹配，无法保证覆盖未知格式的密钥；这是已声明的残余风险（见 §6），界面文案不得承诺“绝对安全”。

## 5. 链接格式、版本、撤销与保留

### 5.1 Phase 1：文件即分享

- 无 URL。产物是文件，命名沿用现有约定：单个会话 `ateam-session-<标题 slug>-<时间戳>.<json|jsonl|md>`，多会话 `ateam-sessions-<时间戳>.<ext>`。
- 版本：文档内 `kind` + `schemaVersion`。导入端只接受不高于当前版本（当前为 1）的文档，更新版本给出明确“请升级 ATeam”错误。
- 撤销：**不存在**。文件一旦离开本机即为用户自行管理的副本；界面必须提示“分享后无法撤回”。
- 保留：ATeam 不保留任何副本；产物生命周期由用户与其使用的存储决定。

### 5.2 Phase 2：GitHub Gist

- 链接：GitHub 原生 `https://gist.github.com/<user>/<gistId>`；内容为导出文档本身（明文）。
- 版本：仍由文档内 `schemaVersion` 决定；Gist 只承担分发。
- 撤销：删除 gist（必要时连同历史 revision）；须提示可能已被缓存或镜像。
- 保留：遵循 GitHub 的保留与备份策略；ATeam 不额外留存。

### 5.3 Phase 3：托管分享服务（仅 E2E）

- 链接格式：`https://<share-host>/s/<shareId>#k=<base64url-key>`
  - `<shareId>`：128 位随机、base64url 编码（22 字符），不可枚举、不可猜测。
  - `k`：对称密钥，只存在于 URL fragment；浏览器与 HTTP 客户端不会把 fragment 发给服务器。
  - URL 中不带版本号，保证链接长期稳定；文档版本由密文内的 `schemaVersion` 决定，旧客户端遇到更高版本时提示升级。
- 加密：AEAD（AES-256-GCM 或 XChaCha20-Poly1305），密文包含文档与元数据；服务端只保存密文、大小、创建时间与到期时间。
- 账号：默认**不需要**。创建分享时生成一次性删除令牌，客户端本地保存；删除令牌即撤销凭证。
- 撤销：`DELETE /s/<shareId>` 携带删除令牌，立即删除密文并返回 410；撤销是尽力而为，已转发或缓存的明文副本不可控。
- 保留：默认 TTL 30 天，可延长至 90 天；到期自动删除；删除后备份最多 24 小时内滚动清除；服务端不做内容分析、不建搜索索引、响应带 `X-Robots-Tag: noindex`。

## 6. 威胁模型

### 6.1 资产

1. 会话内容：提示词、代码、文件 diff、工具输出——可能包含第三方机密或个人信息。
2. 供应商凭据与 OAuth token。
3. 本机路径、用户名、项目名等工作环境指纹。
4. 用户身份（Phase 2 的 GitHub 账号）。

### 6.2 对手与场景

| 对手 / 场景         | 说明                                                         |
| ------------------- | ------------------------------------------------------------ |
| 非预期接收者        | 分享对象转发给他人，或链接被误发到公开渠道                   |
| 搜索引擎 / 爬虫     | 公开 Gist 或未加防护的服务被索引、抓取                       |
| 托管方 / 存储提供方 | Phase 2/3 的运营者读取明文或元数据                           |
| 网络攻击者          | 传输链路被窃听或篡改（MITM）                                 |
| 恶意分享文件        | 攻击者构造畸形导入文件，试图触发解析漏洞、路径穿越或资源耗尽 |
| 本机恶意软件        | 读取导出文件或本地缓存（超出应用边界，仅记录）               |

### 6.3 缓解措施与对应关系

- **凭据泄露**：分享链路不接触 `auth.json`；键名与文本模式双重脱敏（§4.3）。
- **路径与身份泄露**：分享强制路径脱敏；附件与快照不打包。
- **公开暴露**：Phase 2 明确标注“未列出 ≠ 私有”；Phase 3 使用不可猜测 ID、`noindex`、无列表接口。
- **传输与托管**：Phase 3 全程 E2E，密钥不进服务端；传输强制 HTTPS。
- **撤销**：Phase 3 删除令牌 + TTL；Phase 2 删除 Gist；Phase 1 无撤销并在 UI 声明。
- **恶意导入**：沿用现有导入硬化——结构校验、id 全量重映射、未知字段丢弃、占位符不当路径使用、运行状态归一；畸形文件拒绝且不改动已有数据。
- **恶意内容执行**：会话内容只按文本渲染；Markdown 内嵌 JSON 只作为数据解析；链接渲染需沿用现有外部链接安全策略。

### 6.4 残余风险（接受并记录）

1. 模式脱敏无法覆盖未知格式的密钥；工具输出中的第三方机密无法自动识别。
2. 一旦分享，任何技术手段都无法保证撤回；Phase 3 的撤销仅是“服务端不再提供访问”。
3. 元数据（时间戳、模型、成本、标题）即使脱敏也可能被用于指纹识别。
4. Secret Gist 可能被搜索引擎收录；删除后仍可能存在镜像。
5. 托管服务引入可用性、滥用与合规责任，Phase 3 启动前必须补齐滥用政策与责任人。

## 7. 账号体系

- **Phase 1 / 同步（BYOS 目录）**：无 ATeam 账号；身份完全由用户所选存储（iCloud、Dropbox、OneDrive、Git 托管）承担。
- **Phase 2（Gist）**：不需要 ATeam 账号，但需要用户自己的 GitHub PAT；PAT 必须走主进程凭据存储（与现有 provider 凭据同一安全等级），最小 scope（`gist`），并支持随时撤销。新增 GitHub 认证属于独立的安全评审项。
- **Phase 3（托管分享）**：默认匿名分享 + 删除令牌；只有配额管理、滥用申诉等场景才需要可选账号，账号体系不作为首版前提。

## 8. 后果

正面：

- 复用已测试的导出 / 导入与脱敏链路，零新增服务端攻击面，符合本地优先定位。
- 分享的隐私行为可以一句话说清：强制脱敏的本地文件，不经过 ATeam 服务器。
- 为后续 Gist / BYOS / E2E 托管预留了明确的链接、版本与撤销语义，不需要推翻当前格式。

负面 / 代价：

- Phase 1 没有短链与预览，分享体验依赖用户手动传递文件。
- 没有真正的“撤回”，用户教育与文案压力大。
- 同步被推迟；BYOS 同步在冲突与删除语义上仍需要独立设计。
- Phase 3 若启动，需要额外的密码学协议评审与运维投入。

## 9. 后续实现拆分建议

建议按独立 issue 逐步落地，顺序即依赖顺序：

1. **分享流程（Phase 1）**：在会话栏增加“分享”动作，复用导出 IPC，强制脱敏预设、展示脱敏摘要、大小上限与不可撤回提示；补充 UI 文案与测试。
2. **脱敏加固**：建立密钥语料测试集（各类真实形态与变体）与模糊测试，覆盖新增 part / 工具输出；脱敏报告（计数与类别）随分享流程输出。
3. **Gist 发布（Phase 2，可选）**：GitHub PAT 的安全存储与授权流程、发布 / 更新 / 删除 Gist、链接展示、限流与错误处理、明确“未列出 ≠ 私有”的文案。
4. **BYOS 同步 MVP（独立 ADR）**：用户自选目录或自有 Git 仓库；按会话分文件、原子写入、mtime / 哈希冲突检测、删除墓碑与冲突合并策略。
5. **E2E 托管分享（Phase 3，条件触发）**：协议规范（密钥派生、AEAD、fragment 传递）、删除令牌、TTL 与备份策略、`noindex`、滥用政策与配额；上线前完成独立威胁模型评审。
6. **安全测试基线**：分享 / 导入路径的 fuzz 与回归测试，纳入版本发布门禁。

## 10. 风险清单

| 风险                      | 概率         | 影响           | 缓解                                                     |
| ------------------------- | ------------ | -------------- | -------------------------------------------------------- |
| 脱敏漏掉未知格式密钥      | 中           | 高（凭据泄露） | 扩充模式库、分享前摘要、语料测试与 fuzz、用户确认        |
| 用户误以为分享可撤回      | 中           | 中（内容扩散） | UI 明确提示、文档说明；Phase 3 用 TTL + 删除令牌降低影响 |
| Secret Gist 被索引 / 镜像 | 中           | 中             | 明确“未列出 ≠ 私有”；敏感内容优先文件分享或 E2E 托管     |
| PAT 泄露                  | 低           | 高             | 主进程凭据存储、最小 scope、可撤销、独立安全评审         |
| 托管服务滥用 / 合规       | 低（未启动） | 高             | Phase 3 前补齐滥用政策、责任人与法律评审                 |
| 分享文档过大导致导入缓慢  | 低           | 低             | 10 MB 上限、提示拆分、流式解析评估                       |
| 同步冲突导致会话丢失      | 中（BYOS）   | 高             | 独立 ADR 设计原子写、冲突检测与墓碑；默认保留双方副本    |
| 恶意导入文件触发解析漏洞  | 低           | 高             | 现有结构校验 + 全量 id 重映射 + fuzz 门禁                |

## 11. 不在本 ADR 范围

- 实时协作、评论、在线预览与富文本渲染。
- 附件上传与云存储。
- ATeam 账号体系与计费。
- 同步协议细节（冲突合并、墓碑、增量编码）。
- Phase 2 / Phase 3 的具体实现与运维方案。
