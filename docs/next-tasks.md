# ATeam 后续任务清单

> 基线：`cd78477`（Electron 45 + React 19 + Vite 8 + Tailwind 4 + Ant Design 6，OpenCode 源码内核已内置并完成 ATeam 品牌化）。
> 本文只列「接下来需要做的事」，已完成项放在基线里，不重复排期。

## 一、当前基线

已完成：

- pnpm + Turborepo monorepo：`apps/desktop`、`apps/web`、`packages/shared`
- Electron 主进程、preload、contextIsolation、CSP、electron-builder 打包
- Nomi 2.4.0 主题令牌、7 套主题 + 跟随系统、AntD 同步换肤
- 简体中文 / English，AntD locale 与 `<html lang>` 同步，设置页可切换并持久化
- OpenCode 源码内置在 `apps/desktop/src/runtime/opencode`（41 MB，裁剪到构建闭包，已品牌化为 ATeam）
- Electron `KernelManager` 启动内置 `opencode serve`，回环 HTTP + SSE、Basic Auth、隔离 XDG 数据目录
- 会话创建、prompt、消息读取、停止、错误展示、内核重启
- 打包验证：内置内核从 `Contents/Resources/opencode/opencode` 启动

当前阻塞：

- 内核数据目录隔离后没有 Provider 凭据，默认免费模型触发 `Free usage limit reached`
- 会话 UI 仍以轮询刷新为主，工具调用/变更/权限没有完整展示
- 工作目录固定为应用 `userData/workspace`，还没有项目选择

## 二、优先级定义

- **P0**：不做就无法正常使用内核，必须优先完成
- **P1**：日常可用性与体验，决定是否愿意长期使用
- **P2**：产品化、安全、分发与长期维护

## 三、P0：让内核真正可用

### P0-1 Provider 配置与认证

**目标**：用户可以在 ATeam 内配置至少一个模型供应商，并让内核使用它。

**工作项**：

- 设置页新增「模型供应商」：OpenAI-compatible Base URL、API Key、模型 ID、默认模型
- 凭据存储：优先系统钥匙串；不可用时使用本地加密存储，不落明文
- 将 Provider 配置注入到内核：写入内核配置/认证存储，或通过环境变量/配置内容传给 `opencode serve`
- 「测试连接」：使用内核的模型接口做一次最小请求
- 错误处理：401/429/余额不足/模型不存在分别展示可操作提示

**验收**：配置 DeepSeek/OpenAI 后，新建会话发送 prompt，能收到真实模型回复；重启应用后配置仍生效。

**依赖**：无。**估算**：3–5 天。

### P0-2 模型目录与模型选择

**目标**：会话可以选择模型，而不是只能使用免费默认模型。

**工作项**：

- 从内核读取模型目录（`GET /api/model` 或等价 API）
- 设置页维护默认模型；新会话继承默认模型
- 会话头部/输入框提供模型选择器，切换后调用内核的模型切换接口
- 模型不可用、免费额度、上下文长度在 UI 中明确标识

**验收**：至少两个模型可切换，下一次 prompt 使用新模型；刷新/重启后会话模型保持。

**依赖**：P0-1。**估算**：2–3 天。

### P0-3 项目选择与工作目录

**目标**：用户可以选择本地仓库，内核在正确的目录里工作。

**工作项**：

- 原生目录选择（Electron dialog），只允许用户明确选择的项目目录
- 项目列表：最近打开、移除、重命名显示名
- 新建会话时把项目目录传给内核 `location.directory`
- 项目级持久化；应用重启后恢复
- 空项目/权限不足目录的错误提示

**验收**：选择两个不同仓库，分别建会话，Agent 能在对应目录读写；不再固定写入 `userData/workspace`。

**依赖**：无。**估算**：3–4 天。

### P0-4 流式会话 UI

**目标**：Agent 的输出、工具调用、文件变更实时显示，而不是靠轮询。

**工作项**：

- 消费 `/api/event` SSE，按 `sessionID` 过滤当前会话
- 文本增量渲染；工具调用卡片（名称、状态、输入摘要、输出/错误）
- 会话繁忙/空闲、停止、错误状态
- 断线重连后刷新消息快照，SSE 事件去重
- 大输出折叠/截断，避免阻塞渲染

**验收**：一次包含多个工具调用的会话中，文本逐段出现、工具状态实时更新；停止按钮能中止当前执行。

**依赖**：P0-1。**估算**：4–6 天。

### P0-5 权限审批

**目标**：工具执行前由用户明确批准，而不是默认全权执行。

**工作项**：

- 接入内核的 permission 请求（命令、文件修改）
- UI 展示动作、目标路径/命令、风险说明；允许一次/拒绝/始终允许
- 与 ATeam 的路径/命令策略合并：内核请求必须同时满足 ATeam 策略
- 审批结果写回内核；拒绝后 Agent 收到可见错误
- 审批记录与审计事件

**验收**：首次执行 shell/写文件时出现审批；拒绝后命令不执行；允许一次后继续。

**依赖**：P0-4。**估算**：4–6 天。

### P0-6 内核生命周期与恢复

**目标**：启动慢、端口冲突、崩溃、升级时应用不失去控制。

**工作项**：

- 启动进度与超时（当前实测约 8–10 秒），失败可重试
- 端口分配冲突重试；密码只在主进程内存中使用
- 内核退出时 UI 明确提示，支持一键重启
- 应用退出时优雅终止内核进程组
- 内核日志落盘（滚动、脱敏），设置页可打开目录
- 版本握手：记录源码 commit / 内核版本，更新后清理不兼容数据

**验收**：手动 kill 内核后 UI 显示离线并可恢复；连续重启 10 次无残留进程/端口。

**依赖**：无。**估算**：2–3 天。

### P0-7 源码构建可复现

**目标**：任何开发者都能从仓库源码构建出与发布一致的内核。

**工作项**：

- 固定 Bun 版本（`BUN_BIN` / `.tool-versions` / CI 安装脚本）
- 构建脚本校验 `SOURCE_COMMIT`、品牌化结果与产物版本
- CI 构建 macOS arm64/x64（后续 Windows/Linux），缓存 Bun 依赖
- 产物校验和、许可证/NOTICE 随包
- 明确源码更新流程：替换 `apps/desktop/src/runtime/opencode` → 重新品牌化 → 构建 → 回归

**验收**：干净 clone + `pnpm install` + `pnpm opencode:build` 可复现内核；CI 通过。

**依赖**：无。**估算**：3–4 天。

### P0-8 品牌化收尾

**目标**：用户可见文案不再出现 OpenCode，内部兼容标识保留。

**工作项**：

- 全局扫描用户可见字符串：窗口标题、帮助、错误、系统提示、会话默认标题
- 检查 `opencode` / `OpenCode` 残留，区分产品文案与必须保留的服务/API 标识
- 应用名、`productName`、macOS bundle 名称、关于页、日志头部统一为 ATeam
- 默认会话标题改为 ATeam 语义，不暴露上游名称
- 品牌化脚本增加“残留检查”，CI 失败于新增的可见 OpenCode 文案

**验收**：UI、CLI 帮助、`--version`、系统提示、错误提示中产品名均为 ATeam；服务名（OpenCode Console/Go/Free/Zen/SDK）按约定保留。

**依赖**：P0-7。**估算**：2–3 天。

## 七、关键决策与风险

1. **数据目录策略**：当前内核使用隔离的 `userData/opencode`，用户原有的 OpenCode 登录/模型不会自动可用；需要决定「在 ATeam 内重新配置」还是「提供导入本机 OpenCode 配置」。这是 P0-1 的前置决策。
2. **Provider 认证无法规避**：Claude Code 闭源且需要订阅；OpenCode 的免费模型有限额。产品必须接受 BYOK。
3. **源码 fork 成本**：当前只保留构建闭包，仍包含 CLI/TUI/UI 约 41 MB；若要彻底 server-only，需要自写 serve 入口并删除 CLI/TUI/UI。
4. **包体与启动**：内置内核 204 MB，启动约 8–10 秒；需要评估是否接受，或改为按需下载/首次安装。
5. **上游服务名**：`OpenCode Console/Go/Free/Zen/SDK` 是实际服务/SDK 名称，品牌化时保留；不要为了“全替换”破坏认证或 API。
6. **安全边界**：当前内核以当前用户身份运行，审批与沙箱是下一步重点；在 P0-5/P2-1 完成前不要把产品定位为“安全隔离”。

## 八、建议的下一步

先决策 **数据目录策略**，然后按顺序执行：

1. P0-1 Provider 配置（解除免费额度阻塞）
2. P0-2 模型选择
3. P0-3 项目选择
4. P0-4 流式 UI / P0-5 审批

完成 1–3 即可让内核真正可用于日常对话；4–5 决定是否达到“可长期使用”的体验。
